# Plan 02-02: Multipart Application Ingestion, Secure File Storage & Role-Isolated Tracking

## Objective
Build the application ingestion pipeline supporting multipart document uploads, salted Aadhaar tokenization, file safety verification (MIME and size <= 5MB), composite key generation, persistent database storage, and citizen/admin role-isolated tracking endpoints.

## Context
- Citizens apply for PM-KISAN by submitting extensive personal, identity, land, and banking data alongside land ownership deeds or revenue receipts.
- Privacy constraint: Raw Aadhaar numbers must never be saved in any database column or logged. Only `aadhaar_ref` (salted SHA-256) and `aadhaar_masked` (`XXXX-XXXX-1234`) are retained.
- Files must be stored securely in `backend/uploads/` with sanitized, non-colliding filenames.
- Security constraint: Role isolation dictates that citizen applicants querying `GET /api/applications/my` or `GET /api/applications/{id}` can only see their own applications and can never see risk scores, confidence ratings, or internal anomaly rationale.

## Tasks

<task id="1">
<title>Implement Application Service and File Storage</title>
<action>
Create `backend/app/services/application_service.py`:
1. `save_upload_file(upload_file: UploadFile) -> str`:
   - Validates file extension against allowed list: `{.pdf, .jpg, .jpeg, .png}`.
   - Validates file content length / size <= 5MB (5 * 1024 * 1024 bytes).
   - Generates a collision-safe filename: `land_doc_{uuid4().hex[:12]}_{int(time.time())}.{ext}`.
   - Writes the file to `backend/uploads/` in chunks.
   - Returns the stored relative path `/uploads/{filename}`.
2. `create_application(db: Session, current_user: User, ...)`:
   - Validates mock OTP (`123456`). If invalid, raises 400 Bad Request ("Invalid mobile verification OTP").
   - Validates 12-digit Aadhaar. If invalid, raises 400 Bad Request ("Invalid 12-digit Aadhaar number format").
   - Validates IFSC format. If invalid, raises 400 Bad Request ("Invalid IFSC code format").
   - Validates land area > 0.
   - Computes `aadhaar_ref = hash_aadhaar(raw_aadhaar)`.
   - Computes `aadhaar_masked = mask_aadhaar(raw_aadhaar)`.
   - Computes `parcel_id = generate_parcel_id(...)`.
   - Computes `bank_account_ifsc_key = generate_bank_ifsc_key(...)`.
   - Saves uploaded document using `save_upload_file`.
   - Creates `Application(user_id=current_user.id, scheme_code="PM_KISAN", status="SUBMITTED", submitted_at=utcnow)`.
   - Creates `PMKisanApplicationDetails(...)`.
   - Commits transaction and returns the application record with details.
3. `get_user_applications(db: Session, user_id: int) -> List[Application]`:
   Returns applications submitted by the given user.
4. `get_application_by_id(db: Session, application_id: int) -> Optional[Application]`:
   Returns application with joined `pm_kisan_details`, `anomaly_report`, `anomaly_flags`.
</action>
<verify>
Unit test service functions with in-memory or test SQLite DB.
</verify>
<done>
`backend/app/services/application_service.py` implemented with upload handling, Aadhaar privacy tokenization, and DB persistence.
</done>
</task>

<task id="2">
<title>Implement Application Routes with Role Isolation</title>
<action>
Create `backend/app/routes/application_routes.py`:
1. `POST /api/applications/pm-kisan`:
   - Accepts multipart/form-data with all PM-KISAN fields and `land_document: UploadFile`.
   - Enforces `current_user = Depends(get_current_user)`.
   - Calls `application_service.create_application`.
   - Returns 201 Created with `ApplicationSubmissionResponse` containing `application_id`, `scheme_code`, `status`, `citizen_status_message`, `submitted_at`, `parcel_id`, and `aadhaar_masked`.
2. `GET /api/applications/my`:
   - Enforces authenticated user.
   - Returns list of applications as `List[CitizenApplicationSummary]` with sanitized citizen messages.
3. `GET /api/applications/{id}`:
   - Enforces authenticated user.
   - If `current_user.role == "USER"`, checks that `application.user_id == current_user.id` (returns 403 if unauthorized).
   - If `current_user.role == "USER"`, returns `CitizenApplicationDetail` strictly omitting risk scores, confidence rating, and anomaly flags.
   - If `current_user.role == "ADMIN"`, returns `AdminApplicationDetail` with full internal scoring and flags.
4. Register `application_routes` router in `backend/app/main.py`.
</action>

Endpoint registration verified via OpenAPI schema inspection.
