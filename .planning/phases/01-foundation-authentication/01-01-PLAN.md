# Plan 01-01: Backend Foundation, Database Schemas & Security Infrastructure

## Objective
Establish the foundational FastAPI backend architecture, configure SQLite database connectivity with SQLAlchemy ORM models covering all 11 application and master tables, and build the cryptographic security services (bcrypt password hashing, JWT token generation, role verification).

## Context
- Domain: PM-KISAN subsidy scheme and fraud detection system.
- Database: SQLite with SQLAlchemy 2.0.
- Privacy rule: Raw 12-digit Aadhaar numbers must never be persisted; secret salt is used for SHA-256 tokenization.
- Security: Passwords hashed with bcrypt; access tokens signed with HMAC-SHA256 (JWT).

<task id="6">
<title>Implement Cryptographic Security, Password Hashing & JWT Auth Utilities</title>
<action>
Create `backend/app/auth.py`:
- Initialize passlib `CryptContext(schemes=["bcrypt"], deprecated="auto")`.
- `hash_password(password: str) -> str`: return bcrypt hash.
- `verify_password(plain_password: str, hashed_password: str) -> bool`: verify password hash.
- `create_access_token(data: dict, expires_delta: Optional[timedelta] = None) -> str`: encode JWT with expiration, user_id, email, and role claims.
- `get_current_user(token: str = Depends(OAuth2PasswordBearer), db: Session = Depends(get_db)) -> User`: decode JWT, extract user_id, query user from database, handle expired/invalid tokens with 401 HTTP errors.
- `require_role(required_role: str)`: dependency factory returning a checker that raises 403 Forbidden if `current_user.role != required_role`.
- `hash_aadhaar(aadhaar: str) -> str`: helper computing SHA-256 hash using `settings.AADHAAR_SALT`.
- `mask_aadhaar(aadhaar: str) -> str`: helper returning `XXXX-XXXX-{last4}`.
</action>
<verify>
Test hashing and verifying passwords, token creation and decoding, and role checking with test mock data.
</verify>
<done>
Authentication service ready with password hashing, token encoding/decoding, role guard, and Aadhaar privacy helpers.
</done>
</task>
