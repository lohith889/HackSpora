# Plan 01-02: Authentication APIs, Application Factory & Automated Test Suite

## Objective
Implement the authentication endpoints (`POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`), configure the main FastAPI application with CORS and database lifecycle management, and author a comprehensive automated test suite verifying all Phase 1 authentication requirements.

## Context
- Connects the Pydantic schemas, SQLAlchemy models, and security services created in Plan 01-01 into active REST API endpoints.
- Role-based access control must guarantee that JWT tokens carry the appropriate role claim (`USER` or `ADMIN`).
- Ensures clean CORS configuration so the upcoming React/Vite frontend (port 5173) can communicate seamlessly with the backend (port 8000).

## Tasks

<task id="1">
<title>Implement Authentication API Routes</title>
<action>
Create `backend/app/routes/__init__.py`.
Create `backend/app/routes/auth_routes.py`:
- Initialize `router = APIRouter(prefix="/auth", tags=["Authentication"])`.
- Implement `POST /api/auth/register`:
  - Check if email already exists in `users` table; raise 400 Bad Request if already registered.
  - Hash password with `hash_password(user_in.password)`.
  - Create new `User` record with role `USER`.
  - Add and commit user to database.
  - Create access token with `create_access_token(data={"sub": str(user.id), "email": user.email, "role": user.role})`.
  - Return `Token(access_token=token, token_type="bearer", user=user)`.
- Implement `POST /api/auth/login`:
  - Query user by email.
  - Verify password with `verify_password(credentials.password, user.password_hash)`.
  - If invalid user or password, raise 401 Unauthorized (`Invalid email or password`).
  - Create access token with expiration and role.
  - Return `Token(access_token=token, token_type="bearer", user=user)`.
- Implement `GET /api/auth/me`:
  - Protected endpoint with `Depends(get_current_user)`.
  - Return authenticated user profile (`UserResponse`).
</action>
<verify>
Inspect routes and parameter signatures to confirm Pydantic request/response binding and status codes.
</verify>
<done>
Register, login, and me endpoints implemented with complete error handling and JWT issuance.
</done>
</task>

<task id="3">
<title>Author Automated Authentication & Role Security Test Suite</title>
<action>
Create `backend/tests/__init__.py`.
Create `backend/tests/test_auth.py`:
- Use `pytest` and `httpx.AsyncClient` or `starlette.testclient.TestClient`.
- Configure an in-memory SQLite database or isolated test database for test runs.
- Test 1 (`test_register_user`): Register farmer with valid details, assert 200/201 response, valid JWT token in response, and password hash not returned in plaintext.
- Test 2 (`test_register_duplicate_email`): Attempt registering with the same email twice, assert 400 Bad Request.
- Test 3 (`test_login_success`): Log in with registered credentials, assert 200 OK, valid JWT token returned with role `USER`.
- Test 4 (`test_login_invalid_password`): Attempt login with incorrect password, assert 401 Unauthorized.
- Test 5 (`test_get_current_user_me`): Call `/api/auth/me` with Bearer token, assert 200 OK and matching user email and role.
- Test 6 (`test_get_current_user_unauthorized`): Call `/api/auth/me` without Bearer token or with invalid token, assert 401 Unauthorized.
- Test 7 (`test_role_guard`): Define a test endpoint protected by `require_role("ADMIN")`; assert `USER` token receives 403 Forbidden and `ADMIN` token receives 200 OK.
</action>
