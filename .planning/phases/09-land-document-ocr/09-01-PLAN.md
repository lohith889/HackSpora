# Plan 09-01: Land Document OCR Engine, Entity Parser & Anomaly Engine Integration

## Objective
Implement an automated, offline Land Document OCR and entity extraction service for PM-KISAN subsidy applications. When a land deed (PDF, JPG, PNG) is uploaded, extract the Land Document ID / Parcel ID, Khasra/Plot number, Khata number, Owner Name, and Land Area. Deterministically reconcile extracted entities against the application claims and master records, assign match statuses (`MATCHED`, `MISMATCH`, `UNVERIFIED`), and trigger Land Engine anomaly flags (`LAND_DOC_ID_MISMATCH`, `LAND_DOC_OCR_UNREADABLE`) for Scheme Officer triage.

## Context & Architecture Contracts
- Consumes [`09-RESEARCH.md`](file:///D:/lohith/hackspora/.planning/phases/09-land-document-ocr/09-RESEARCH.md).
- **Offline Invariant**: Zero cloud dependencies. Runs 100% locally using PyMuPDF (`pymupdf`), `pypdf`, `Pillow`, and `easyocr`.
- **Statutory Invariant**: If an uploaded deed explicitly certifies a different parcel ID or plot than claimed, flag as `LAND_DOC_ID_MISMATCH` (Severity: High, Score: 40).
- **Zero Citizen Exposure**: Internal OCR match statuses and anomaly flags remain strictly within administrative boundaries (`/admin/*`) and are not leaked to citizen status views.

### 3. Core Land OCR & Entity Extraction Service (`OCR-01`, `OCR-02`, `OCR-03`)
- Create [`backend/app/services/land_ocr_service.py`](file:///D:/lohith/hackspora/backend/app/services/land_ocr_service.py):
  - `extract_text_from_file(file_path: str) -> str`:
    - Reads digital PDFs via `pymupdf` (`page.get_text()`) or `pypdf`.
    - Handles images (`.jpg`, `.png`) or scanned PDFs using `Pillow` and `easyocr` (with safe fallback to visual text blocks).
  - `parse_land_entities(text: str) -> dict`:
    - Applies regex patterns for:
      - Document ID / Registration Ref (`DOC-...`, `REG-...`, `UP-LKO-...`)
      - Khasra / Plot Number (`(?:Khasra|Plot|Survey|Gata)\s*[:\-#]?\s*([A-Z0-9\/\-]+)`)
      - Khata / Khatauni Number (`(?:Khata(?:uni)?)\s*[:\-#]?\s*([A-Z0-9\/\-]+)`)
      - Land Area (`(?:Area|Rakba)\s*[:\-#]?\s*([0-9]+(?:\.[0-9]+)?)`)
      - Titleholder Name (`(?:Owner|Titleholder|Farmer|Bhumidhar|Malik)\s*[:\-#]?\s*([A-Za-z\s\.]{3,50})`)
  - `reconcile_land_document(extracted: dict, declared_parcel_id: str, declared_khata: str, declared_plot: str, declared_name: str) -> dict`:
    - Evaluates match status (`MATCHED` if ID or Plot+Khata match declared claim; `MISMATCH` if a distinct ID is extracted that conflicts with claim; `UNVERIFIED` if text is empty/unreadable).
    - Calculates evidential `ocr_confidence_score` (0.0 to 1.0).
  - `process_uploaded_land_document(file_path: str, declared_parcel_id: str, declared_khata: str, declared_plot: str, declared_name: str) -> dict`:
    - Full end-to-end extraction and reconciliation runner returning structured dictionary for database persistence.

### 4. Anomaly Engine Integration (`OCR-04`)
- Update [`backend/app/services/land_engine.py`](file:///D:/lohith/hackspora/backend/app/services/land_engine.py):
  - Check `details.ocr_match_status` and `details.ocr_status`:
    - If `ocr_match_status == "MISMATCH"`:
      - Emit `LAND_DOC_ID_MISMATCH` (Severity: `High`, Score: `40`, Rationale: *"Uploaded land deed ID '{extracted_id}' conflicts with claimed parcel '{parcel_id}'. Possible forged or recycled document."*).

      - Emit `LAND_DOC_OCR_UNREADABLE` (Severity: `Medium`, Score: `20`, Rationale: *"Uploaded land deed document is unreadable or contains no identifiable revenue markers. Officer manual review required."*).
